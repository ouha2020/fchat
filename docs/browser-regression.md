# 浏览器回归与真机验收

## 本地运行

```bash
npm ci
npx playwright install chromium
npm run test:e2e
```

已安装 Chrome 的 Windows 机器也可运行：

```powershell
$env:PLAYWRIGHT_CHANNEL = 'chrome'
npm run test:e2e
Remove-Item Env:PLAYWRIGHT_CHANNEL
```

`playwright.config.ts` 自动启动 `127.0.0.1:3101` 的独立 Next 开发服务，不复用现有登录服务。3101 必须空闲。测试关闭后由 Playwright 回收该服务；与 `npm run build` 顺序运行，避免同时写 `.next`。

测试服务的公开 Supabase 配置固定指向 `127.0.0.1:4319`，使用无权限的合成凭证。浏览器 fixture 拦截 RPC、Realtime、签名及上传；未声明的 API/RPC 和外部 HTTP 请求会被拒绝并使测试失败。模拟只存在于 `tests/browser`，不向产品页面注入测试权限或假数据入口。不需要真实账号、生产数据库或 Storage。

默认关闭 Service Worker、截图、视频和 trace。用例产生的是合成草稿与浏览器隔离缓存，上传不写入远端 Storage。CI 安装 Chromium 后运行同一套用例。配置依据：[Playwright webServer](https://playwright.dev/docs/test-webserver)、[网络与 WebSocket 模拟](https://playwright.dev/docs/api/class-browsercontext#browser-context-route-web-socket)。

## 固定覆盖

- 日程实时事件触发实际页面刷新，保留评论草稿、私密接收人和编辑内容。
- 初次详情慢响应、关闭后响应、A/B 切换、评论提交期间继续输入。
- 个人页 focus/visibility 并发刷新去重，过期结果不能恢复已删除头像或显示旧错误。
- Dialog Tab/Shift+Tab 焦点圈、Escape 取消与触发焦点恢复。
- 头像上传离开页面时 XHR 中止，取消后不调用头像保存 RPC。
- 360px、390px、430px 宽度与 520px 压缩高度：横向滚动、评论输入和发送按钮。
- 1000 条聊天记录分页，观察器数量、历史/末尾锚点、消息菜单及卸载资源清理。
- 长历史后的文字发送与撤回、语音/位置发送、图片上传中收到 Realtime、真实 ID 替换和重复事件：已加载历史保留，旧快照不恢复撤回内容；缓存回写与新消息副作用分别处理。
- 实际缓存源码在独立合成 HTML 中运行原生 IndexedDB：1000 条容量/最近 100 条、客户端临时字段剔除、事务失效中止、旧清理保留新登录数据、同步 seq 单调及无版本旧缓存重建。测试观察缓存时先查询数据库是否存在，不创建空库影响产品初始化。
- 两个实际浏览器标签页共享本地身份：另一页判定身份过期后，受控延迟同步不能恢复消息/游标；同身份重新登录的新消息仍可保存，旧响应被丢弃。
- 首页/加入及相册/成员/设置/个人/日程的身份恢复晚响应不能覆盖替换后的 session；共享退出立即卸载已显示内容与弹窗。原生 Cache API 的媒体写入按共享会话版本隔离，旧下载和旧清理不能影响新登录。
- 发送成功后立即阅读历史：控制释放剩余的 520ms 底部跟随回调，旧消息仍在视口。先在旧实现复现失败，再核验修复；原有 1000 条发送/撤回/重复 Realtime 的定位断言保留。
- 真实消息组件的图片预览、生成音频播放/自然结束、位置、悄悄话与撤回展示。
- 合成麦克风授权允许/拒绝、延迟授权、取消后重录、后台取消、日程关闭/切换、视口变化。正常发送使用浏览器原生 MediaRecorder 录制合成音频，验证上传与消息展示；不调用硬件麦克风。上传中关闭会中止；已提交的日程记录保留协作通知，关闭后不恢复旧详情。
- 消息通知冷入口、连续不同目标、连续日程提醒、外家庭信号忽略。Service Worker 的通知点击、窗口导航失败回退、客户端安全信号及家庭范围清理另有单元回归；没有发送系统 Web Push。

消息缓存的数据库版本和索引保持不变；消息及同步状态新增随机会话版本标记，不新增持久化凭证。没有标记的旧本地消息会经授权 RPC 重建，首次同步前可能暂时缺少离线历史；服务器数据不受影响。

`npm run test` 另行覆盖观察器资源上限、移除后的通知、Strict Mode 重挂载、浏览器降级，以及现有上传、缓存、消息同步、Push 等单元回归。

## 数据库权限回归

`tests/database/permission-matrix.sql` 使用两户合成家庭和五个合成身份（发送者、接收者、非参与成员、非参与管理员、另一家庭成员），以 `anon` 实际角色调用现有 RPC。覆盖悄悄话、私人日程、协作/媒体记录、评论写入、移除成员后旧身份读写，以及数据库 recipient 来源。媒体引用是不存在的测试路径，不创建 Storage 对象，也不调用 Push 服务。

脚本的异常子事务会强制回滚全部测试数据和触发器写入；任何非预期错误也会回滚。成功后再次核对测试家庭、成员、消息、日程和记录不存在，只输出通过项与回滚状态。它不是 migration，不创建或修改函数、表、policy 或 grant。仅在确认目标项目后通过 SQL 编辑器/psql 运行完整脚本；不要拆开运行或替换为真实家庭身份。

媒体签名 API 的本地回归执行真实 route，模拟成员验证和数据库查询，核对 recipient、家庭、引用匹配与撤销后的拒绝路径。该回归不等同于实际生产 API/Storage 端到端验收。

## 必须另行验证的边界

2026-10-05 商用首版复验已在 fchat 生产数据库执行上述回滚脚本：18 个检查通过，实际 RPC 角色为 `anon`，五个合成身份完成可见性及移除后读写验证，新增历史 `create_family` 不向 PUBLIC/anon/authenticated 开放的检查；所有测试行已回滚，没有创建 Storage 对象。`20261005_revoke_legacy_family_creation` 撤权 migration 已应用，现代 owner 创建 RPC 仍仅服务端可执行。当前健康 catalog 的数据库范围 262 项通过，无失败或警告；不包含部署环境 secrets。图片/语音 bucket 为 private。该结果没有覆盖生产 HTTP 签名请求或真实通知投递。

模拟 RPC 只能验证页面处理返回数据的行为；数据库回归验证实际 RPC 权限，媒体 API 的本地回归仍使用模拟数据库。发布前补齐以下实网/真机检查；不要拿真实家庭隐私内容做截图或日志。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 悄悄话 | A 给 B 发送文字/媒体；C 和非参与管理员读取 | 只有 A/B 可读；其他身份无法通过 RPC 或签名取得内容 |
| 私人日程 | A 创建并指定 B，C/管理员读取详情、评论、媒体 | 仅创建者和负责人可见；拒绝行为在服务端生效 |
| 移除成员 | 移除 C 后，用 C 旧 session 再读写和签名 | 新读取、写入和签名均失败；已签 URL 的过期限制按既有规则处理 |
| iOS/Android PWA | 打开软键盘、输入长草稿、横竖屏切换、滚动详情 | 输入栏稳定，保存/发送可达，无横向滚动或明显晃动 |
| 真机录音 | 允许/拒绝麦克风；发送、取消、视口改变、播放 | 拒绝有提示；取消不发送；播放正常，上传失败可恢复 |
| 通知 | 前台/后台发送；连续点击两个不同消息通知和一个日程提醒 | 前台尽量无系统通知；各次分别定位到目标；payload 为安全摘要 |

生产健康对账与 Vercel 发布继续遵守 `AGENTS.md`。浏览器测试本身不进行部署、数据库 migration 或生产权限修改；本轮生产撤权迁移与数据库回滚验证单独记录在 `docs/commercial-readiness.md`。
