## 先处理 Auth 入口

1. 在 fchat 管理台 Authentication → Sign In / Providers → User Signups 查看 `Allow new users to sign up`，目标为关闭；不修改 Email provider、Confirm Email、既有用户或密码。
2. 本仓库的创建者注册经 `/api/auth/register` 调用服务端 `auth.admin.createUser`；`lib/accountClient.ts` 没有直接 `signUp`。保留这一入口和邀请名单，在隔离环境验证受邀创建者注册、既有登录和密码恢复。
3. 保存后重新只读查询 `/auth/v1/settings`，必须明确得到 `disable_signup=true`。记录开关前后布尔值，不能只凭按钮点击认定修改成功。
4. 在隔离环境用专属测试邮箱检查直接 Auth signup 被拒绝；受邀 API 注册成功且只产生一次验证码邮件。配置读取通过与业务正/反向验证分别记录。
5. 未完成 E04 与上述业务验证前，S38 不能勾选完成。生产开关变更不是数据库 migration；无需修改 schema/RPC，也不能用 SQL 修改托管 Auth 配置。

## 备份恢复演练

Supabase [数据库备份不包含 Storage 文件本体](https://supabase.com/docs/guides/platform/backups)，必须分别保管数据库备份与图片/语音/头像文件，不能把 Storage 元数据恢复当成媒体恢复。

1. 明确隔离源/恢复目标、负责人、允许数据损失 RPO 与恢复时间 RTO。现有平台备份是否可用单独核对，不假定已购买任何计划/附加服务。
2. 先用合成家庭完成备份→隔离恢复流程。产物放在获准的受控位置，记录备份时间、完整性摘要和范围；不放进 Git，也不导出真实 token/hash/家庭正文到测试报告。
3. 恢复目标在导入前阻断邮件/Push/cron 外发；不复制生产 vault 密钥、真实收件箱/订阅端点，不让恢复的任务重新启用外发。不得覆盖、暂停或恢复生产项目。
4. 对账 owner/member、messages/message_recipients、family_seq、日程/评论/负责人、媒体引用与实际对象，检查 private buckets、RLS、RPC、grant、Realtime 和 schema health。
5. 以恢复后的五身份再次检查可见性/签名，实际下载测试图片、播放测试语音，确认“有消息但无媒体”的故障可被识别。记下实际恢复耗时及损失窗口，不能填写估算值当实测值。
6. 精确清理本轮合成对象。实际生产备份的恢复能力仍需受控的隔离演练与记录；合成流程通过不能替代这项证据。

- 新建测试对象必须记录 run ID、项目/家庭/对象 ID 的归属，清理只使用本轮精确清单；不按昵称模糊删除，不遍历真实家庭正文。
