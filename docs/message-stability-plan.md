## 第一步：保留已加载历史，统一消息回写（S32 / P1）

### 实现步骤

1. 列出所有消息数组提交入口：启动恢复、历史分页、Realtime 单条/批量拉取、通知补拉、文字/图片/语音/位置发送、撤回、重要通知、主动刷新及轮询。
2. 将缓存返回的最近消息作为增量输入，与当前页面列表按 ID 合并；历史分页仍按现有规则插入并保持锚点。只有明确的身份变化或页面初始化才重置对应状态。
3. 页面提交入口显式接收发起操作的身份，核对当前 family/member/会话仍匹配；没有有效当前身份时丢弃响应。再与第二步的会话版本保护接通。
4. 更新消息按现有排序规则定位；新消息只出现一次，撤回更新同 ID 气泡。补充新旧响应交错回归，如发现旧快照覆盖新撤回，在现有 `messageList` 内增加必要版本判断。
5. 保留图片上传中/失败态、本地预览和真实 ID 替换。缓存写入失败时，已成功的 RPC 消息与当前历史仍保留在页面，不把发送误报成失败。
6. 仅消息数组合并使用纯 `setState` updater；提示、动效、已读/送达上报和 Push 请求仍在 updater 外执行并去重。缓存快照回写不得重新触发一遍副作用。
7. 保留自己的发送滚底、阅读历史时新消息不强制滚底、通知定位优先于旧滚底任务的行为。

### 预计文件

- `app/chat/page.tsx`：消息提交入口、各发送/撤回/通知分支与异步身份检查。
- `lib/messageList.ts`：优先复用现有合并；只有新增用例证实需要时补版本/临时状态处理。
- `lib/messageList.test.ts`、`tests/browser/app-regression.spec.ts`：长历史与发送/撤回/通知的组合回归。
- `tests/browser/fixtures.ts`：按实际用例补图片上传、撤回或事件模拟；保持未声明的外部请求全部拒绝。

## 第二步：让退出与身份切换立即使旧任务失效（S33 / P1）

### 保护模型

采用一份轻量会话版本上下文，贯穿请求开始、网络返回、缓存事务与页面提交。版本属于本地 family/member；凭证仅用于内存与当前 session 的相等性检查，不新增 token/hash 的持久化副本。

建议新增无运行时 Auth/服务依赖的 `lib/messageCacheLifecycle.ts`，提供捕获版本、检查有效性和同步失效能力。`authLocal` 在退出、family/member/token 变化时先同步失效，再异步删除缓存。普通昵称、头像或家庭名称刷新不使当前请求失效。

为了覆盖同身份立即重登和多标签页，版本采用独立随机标识，使用本地元数据跨上下文共享；消息与同步状态携带版本。清理仅删除旧版本数据，读取仅接受当前版本，避免延迟清理删除新登录写入。最终字段/索引在实施时按既有 IndexedDB 结构选择；需要升级时只升级本地缓存版本，无 Supabase migration，旧缓存可清理后经现有 RPC 重建。

### 实现步骤

1. 在请求的第一个异步边界之前捕获上下文；`syncMessages` 的所有分页/降级刷新沿用这一份上下文。返回以后不能重新捕获一个新版本并把旧数据当成新请求。
2. `clearSession` 和身份变更同步更新失效版本；消息缓存删除、媒体缓存删除继续尽力完成，退出无需等待网络或 IndexedDB。
3. 缓存打开后、创建写事务前、事务中的异步回调、提交 UI/副作用前检查上下文。既保护 messages，也保护 sync_state、openCount 和 family_seq checkpoint。
4. IndexedDB 的清理与写入使用可核对的版本条件；已经开始的旧事务要被中止或由后续清理移除，保证清理完成后旧请求不能再次填充。同身份新登录的合法写入不受旧清理影响。
5. 覆盖单条/批量 Realtime、全量/seq/时间游标同步、通知缓存写入、历史分页及发送成功后的缓存回写。页面已卸载/身份变化时丢弃 UI 更新；已被服务端接受的操作不自动重发或尝试撤销。
6. 多标签页通过 `storage` 事件传播会话失效，同时每个读写边界直接复核共享版本与当前 session；事件到达先后不作为唯一保护。旧页退出身份后停止旧同步与回写。
7. 同步锁记录操作 ID；释放只删除自己持有的锁。旧操作超时/失效后的 finally 不得删除另一个新操作获取的锁；锁 TTL、弱网补偿策略继续沿用现有值。
8. localStorage/IndexedDB 受限、打开失败或配额不足时使相应缓存降级；RPC 权限校验继续生效，不凭缓存建立成员身份。失效后的请求不进入旧身份的全量刷新兜底，不显示旧错误提示。

### 预计文件

- `lib/messageCacheLifecycle.ts`：小型会话版本模块，避免引入循环依赖。
- `lib/authLocal.ts`：同步失效和旧版本清理接入。
- `lib/messageCache.ts`：版本字段/事务防护、版本范围读取与清理、可用性降级。
- `lib/messageSync.ts`：操作上下文传递、分页停止、过期兜底抑制及同步锁归属。
- `lib/notificationMessageSync.ts`：将请求开始时上下文传入缓存后台写入。
- `app/chat/page.tsx`：与第一步共用的提交守卫、异步发送/分页/通知接入。
- 相应 `*.test.ts` 与 `tests/browser`：生命周期及真实 IndexedDB 回归。

### 完成标准

| 时序 | 预期 |
| --- | --- |
| 请求暂停 → 退出 → 清理完成 → 放行响应 | 旧 owner 的消息与同步状态均为空；页面不恢复旧身份 |
| A 请求暂停 → 切换 B → 放行 A | 不更新 B 的页面/缓存，不继续发 A 的分页或兜底请求 |
| 退出 A → 立即重新登录 A → 放行退出前请求 | 新会话可正常同步；旧响应不获准写入 |
| 新登录先写入 → 旧清理随后执行 | 只清理旧版本，不删除新版本数据 |
| 同 member 换 token | 旧凭证发起的任务失效；无新增 token 持久化副本 |
| 同身份更新昵称/头像 | 正常同步继续，避免因资料刷新丢弃合法结果 |
| 两个标签页，一个退出或切换家庭 | 另一个旧请求不能重新写入；回到前台也不恢复旧身份 |
| 已进入 IndexedDB 的旧事务遇到退出 | 清理完成后无旧消息/游标残留 |
| 旧锁到期 → 新操作取得锁 → 旧 finally 执行 | 新锁仍归新操作，旧任务不误删 |
| 缓存/本地存储异常 | 无未处理异常；可用的 RPC 读写照常，失效数据不成为缓存兜底 |

| 检查 | 预期 |
| --- | --- |
| A/B 对合成悄悄话媒体请求 `/api/media/sign` | 签名成功，可取回对应合成对象 |
| C/D/E 请求同消息媒体 | 被 API 拒绝，不返回签名 URL |
| 私人日程媒体由参与者/非参与者分别访问 | 权限与已有 RPC/recipient 一致 |

| 篡改引用、跨家庭路径或裸路径 | 拒绝，无底层存储错误泄漏 |
